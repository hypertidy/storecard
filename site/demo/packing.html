The numbers are not the values

NOAA OISST stores sea surface temperature as 16-bit integers: hundredths of a degree, with scale_factor 0.01 and _FillValue -999. That is CF packing, and it halves the bytes before compression. A reader that skips it reads 2846 where the value is 28.46 °C, and draws most of the ocean past the top of the colour ramp; one such reader did exactly that with these fixtures. The card reads the packing from the store's metadata alone, so a reader can apply it before drawing. This page reads f01b (packed, as published) and its twin f01e (the same values stored as float32) from the bucket and compares them cell for cell.

All three panels treat the fill as missing (land and sea ice, drawn grey), so the only thing that varies is packing; fill values are the next page. Without packing, the stored integers run from about -180 to 3300, so every ocean cell above 0.35 °C lands past the top of a -2 to 35 °C ramp: all but the polar water near freezing. With packing applied, the f01b panel and the f01e panel are the same picture.

Cell for cell

comparing

CF says the unpacked type is the type of scale_factor, here float32, so the comparison is done in float32. Unpacking in float64 and stopping there gives values that differ from f01e in the last bits; the line above counts them too. Neither is wrong as temperature, but only one is the same number as the twin's, and a reader checking twins, or a hash of the values, needs to know which.

What the card reads

From each store's sst/zarr.json, no data: the stored type, the packing, every fill source and whether they agree, and the valid range. CF gives valid_min and valid_max in packed units, so f01b's -300 and 4500 mean -3 and 45 °C. The fields below are the card's values block, recomputed in this page from the metadata it fetched.

f01e kept valid_min -300 and valid_max 4500 when it was unpacked. With no packing left, CF reads them in °C. They exclude nothing real, so the picture is unaffected, but they are wrong, and a tool that sets its colour range from them would draw f01e near-uniform. The card records the attributes as found; a finding for a valid range left in packed units is not written yet.

What each reader fetched

Packing halves the stored values, two bytes a cell against four, but zstd closes much of the gap: the float32 twin costs about a third more per day, not twice as much.
